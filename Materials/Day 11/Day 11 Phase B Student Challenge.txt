### Phase B (Part 2) — Fix One More Rough Edge, Properly
 
**The Delta:** Pick **one** item from the list below.

first, understand precisely why the current behavior happens, fix the
actual cause, and verify the fix** — with a `pytest` test where the
issue is backend-side (reusing Day 10's infrastructure), or a clear
manual verification writeup where it's frontend-only (this course
hasn't set up frontend testing — note *why* as a Research Prompt).

### Research Prompts
 
- Frontend code has no automated tests in this project at all — only
  the backend does (Day 10). Look up **Vitest** or **React Testing
  Library**, the standard tools for this. What would a test for
  `Fix 1`'s corrected `LoginForm` error-handling logic actually need
  to simulate?
- `set -e` (Part 1) makes a Bash script stop at the first failure.
  What's the tradeoff — is there ever a case where you'd *want* a
  setup script to keep going even after one step fails?
- Compare today's bug-fixing methodology (reproduce → understand →
  fix → verify) to Day 10's own testing philosophy directly. Is
  "write a failing test that captures the bug, then fix the code until
  it passes" meaningfully different from ordinary test-writing, or is
  it the exact same skill pointed at an existing problem instead of a
  new feature?
